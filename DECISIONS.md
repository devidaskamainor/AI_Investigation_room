## Contract interpretations requiring explicit documentation

- Development origin handling accepts localhost, 127.0.0.1 and ::1 only when both origins use a loopback host and the configured protocol/port. This fixes Vite's advertised 127.0.0.1 URL conflicting with the default localhost CLIENT_URL. CORS and CSRF use the same policy; tokens remain required, and production allows only the exact configured origin. A denied origin now has its own ORIGIN_NOT_ALLOWED response instead of implying that the session changed.

- Original (10.1): “The serialised public payload contains no forbidden key and no culprit id.” The suspect directory necessarily includes every suspect's ID, including the culprit. Interpret the prohibition as no field identifying an ID **as the answer**. The scanner rejects private answer fields, facts, evidence roles, hints arrays and solution metadata; ordinary suspect references remain legal. Affected components: public DTOs and leak-scan tests.
- Original (AC-09): “While a case is active, no response contains the culprit, motive answer, facts, evidence roles or hints.” FR-34 and the hints endpoint require revealing a requested hint. Future hints and the whole hints array remain private; a successful hint request releases one `hint` string. Affected components: hint service and security tests.
- The API needs a public `GET /auth/csrf` endpoint to bootstrap CSRF protection before registration/login, and a demo catalogue/import endpoint when `DEMO_MODE=true`. These support explicitly required capabilities and expose no private case data.
